# Новые правила наименований

1. Любой интерфейс должен начинаться с I: IUser
2. Любое приватное или защищенное поле, но не метод всегда начинается с \_: \_id
3. Любое публичное поле класса или геттер или сеттер или метод всегда начинается с маленькой буквы
4. Любой метод или поле ВСЕГДА должен содержать модификатор доступа - public, private или protected
5. Любое статическое поле (не метод!) всегда начниется с s*: s_Instance (кроме приватного, оно все еще с *)
6. НЕЛЬЗЯ использовать магические числа: либо должен стоять комментарий с объяснением числа, либо оно вынесено в константу
7. Любая константа имеет вид CONSTANT_VALUE
8. Любая переменная кроме константы имеет вид someVariable
9. Нельзя использовать var, только let и const
10. Любая функция должна быть объявлена через const func = () => {};
11. Нельзя использовать this внутри функций (метод - исключение)
12. Нельзя экспортировать изменяемые значения (export let)
13. Использование export default только в исключительных случаях
14. У всех переменных, использующих let, должен быть объявлен тип
15. У всех переменных, использующих const, тип объявлять не нужно (за исключением некоторых случаев)
16. У всех методов и функций должен быть указан возращаемый тип
17. Нельзя использовать bind(), call() и apply() - вместо этого стрелочная функция
18. Вместо return всегда использовать throw new Error()
19. Всегда использовать try {} catch (err) {}
20. Нельзя делать прямое взаимодействие с любым внешним апи, будь то axios, node-telegram-bot-api или openai, в любом классе или в любой функции, который/ая не создан(а) для этого
21. Любой тип должен быть в PascalCase
22. Если используется исключительно тип, необходимо использовать import type {}
23. Любой Union-тип выносится в отдельный тип (кроме | null или чего-то по типу string | Buffer)
24. Запрещено использовать undefined. Всегда только null, кроме следующих случаев
25. Можно использовать undefined (с его последующем изменением или приведением в null) при действии с внешним кодом
26. <em>НИКАКИХ ТИПОВ any!!!</em>
27. Нельзя использовать длинные тернарные операторы
28. Любой объект, возвращаемый чем-либо, обязательно типизируется отдельно
29. Любой объект, не являющийся экземпляром класса, типизируется через type
30. Любой объект, являющийся экземпляром класса, типизируется через interface или тип класса
31. Необходимо стараться использовать объекты исклчительно с классами (за исключением некоторых случаев, указанных ниже)
32. Объект, передаваемый внешнему апи, не требует использования класса
33. В исключительных случаях передачи объекта как параметр в метод или функцию разрешается не использовать класс
34. В классе необходимо стремиться к наибольшему числу неизменяемости и приватности
35. В классе необходимо всегда строго указывать override
36. Все функции, определенные вне класса - чистые функции
37. Запрещено использовать variable! и @ts-ignore
38. Single Responsibility Principle - класс всегда ответственный только за одну вещь.
39. Open/Closed Principle - класс можно расширять, но не изменять его поведение
40. Liskov's Substitution Principle - замена класса на подкласс не должна изменять корректности программы
41. Interface Segregation Principle - интерфейсы должны быть четкими, а не общими.
42. Dependency Inversion Principle - для связи между кодом нужно использовать интерфейсы, а не классы. (только если в будущем может быть добавится другой такой же класс)
